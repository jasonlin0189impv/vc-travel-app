# CLAUDE.md — vc-travel-app

Monorepo of per-trip travel web apps. Each trip is a self-contained React + Vite +
Tailwind app in its own folder (`seoul-trip-2025/`, `honeymoon-trip-2026/`, …).
There is **no traditional backend** — Google Sheets is the database.

## Architecture (read before touching a trip app)

- **Shared component, thin per-trip config.** The whole app lives in
  `shared/components/TripApp.jsx`; each trip's `src/App.jsx` is a ~60-line `config` object
  (`theme`, `ui`, `title`, `members`, `api`, `dates`, `weatherLocations`, …) passed to `<TripApp>`.
  `smartParseCSV` is still exported (tests reference it) but unused at runtime — leave it.
- **Backend = one Apps Script Web App + one spreadsheet (two tabs `Itinerary`/`Expenses`).**
  The client sends `POST { pin, type:'itinerary'|'expense', action, ...payload }` to
  `config.api.url` (the `/exec` URL, from `VITE_<TRIP>_API_URL`): `read` → `{status:'success',data:[...]}`;
  `create`/`update`/`delete` → `{status:'success'}`. Backend is `scripts/gas-setup/Code.gs`
  (`setupTrip()` for new, `initExisting()` to extend an existing sheet) — see its README.
- **Auth is server-side.** The real PIN lives in the web app's Script Properties (`AUTH_PIN`),
  never in the repo/.env/bundle. Login POSTs the entered PIN (`type:'auth'`) for the server to
  verify; every request carries it; a wrong PIN returns `unauthorized` and no data. The web app
  URL is non-sensitive (gated by the server PIN) and lives **hardcoded in `config.api.url`** — no
  env var, no GitHub secret.
- **Split-bill convention:** an expense item name may carry a ` #split:信,屏` suffix naming who
  shares the cost. This is tested — keep it green. It's a UI convention, transport-agnostic.
- Amounts stored in TWD; other currencies shown at a fixed rate (`config.exchangeRates`).

## Google backend & Drive layout

- The whole backend for a **new** trip is generated by one Apps Script: **`scripts/gas-setup/Code.gs`**
  (run `setupTrip()` once, then deploy it as a Web App). See `scripts/gas-setup/README.md`.
  Claude's Drive connector can't deploy Web Apps, so backend setup is GAS, not Claude.
- Each trip's files live in Drive under `旅遊/<地區>自由行/<trip>_YYYY/`. New trips get **one**
  spreadsheet (two tabs) there; `setupTrip()` creates the folder and file in the right place.
  (Legacy `seoul-trip-2025` has two spreadsheets + a form — its older layout.)

## Env & secrets

- **No env vars, no GitHub secrets.** The only per-trip backend value is the web app URL, which is
  non-sensitive (server-PIN-gated) and lives hardcoded in `config.api.url`. `.env` files are now
  vestigial. New trips add **nothing** to the GitHub secrets page.
- The real secret — the login PIN — lives server-side in the web app's Script Properties (`AUTH_PIN`).
- Keep the Google spreadsheets **private** (not "published to web"); the web app reads them as the
  owner. (Legacy trips had a public expense CSV — stop-publish it when migrating.)

## Dev workflow

```bash
cd <trip>-YYYY
npm install
npm run dev        # http://localhost:5173
npm run test       # vitest — MUST pass before deploy
npm run build
```

- **Node 18.**
- **"Done" = `npm run test` passes and `npm run build` succeeds** in that trip's folder. A change
  to split/expense/itinerary logic isn't done until the relevant test passes; add a test when you
  touch that logic.

## Deploy

- GitHub Actions, **manual trigger** (`workflow_dispatch`), one workflow per trip
  (`.github/workflows/deploy-*.yml`). Runs `npm run test` → `build` → publishes to `gh-pages`.
  If tests fail, nothing deploys.
- Working branch is **`develop`**; deploy from `main` or `develop`.

## Adding a new trip

### Intake — collect these from the user first (drives the whole scaffold)

**Required:**
| Input | Feeds |
|---|---|
| 地區/國家 (region) | Drive parent folder `旅遊/<地區>自由行/` (create if missing); weather city; currency |
| 旅程名 + 年份 (name + year) | folder & spreadsheet name, `package.json` name, vite `base`, `config.title` |
| **PIN** | server-side `AUTH_PIN` in Apps Script **Script Properties** — never in repo/.env/bundle |
| 旅遊時間 (dates / 天數) | `config.dates` (per-day labels), `config.title.duration` |
| 旅行人名 (members) | `config.members` (expense payer + `#split:`) |
| 配色 (some hex colors) | User gives *a few* colors; **if fewer than 5, add suitable complementary ones** to fill the 5 roles `base/large/small/text/white`, then expand into `config.ui` (Tailwind needs literal class strings, so `ui` is written out, not computed) |
| 幣別 + 匯率 (currency + rate) | `config.exchangeRates`, `config.baseCurrency` |
| hero 圖 / favicon | `public/` image + `index.html` |

**Derived by Claude — do NOT ask the user:**
- 城市經緯度 for `config.weatherLocations` — look up from the region/cities.

**Optional (have sensible defaults, can fill later):** `config.phrases` + `phraseTitle`,
`config.checklist`, `config.tips`.

### Steps

1. Copy an existing trip folder → `<trip>-YYYY/`; update `package.json` name, `vite.config.js`
   `base`, `index.html` title/favicon. Fill `src/App.jsx` `config` from the intake above.
2. Backend: run `scripts/gas-setup/Code.gs` (`setupTrip()` for a new sheet, or `initExisting(id)`
   to extend one), set `AUTH_PIN` in Script Properties, deploy as a Web App (see its README).
   Hardcode the resulting `/exec` URL into `config.api.url` — no `.env`, no GitHub secret.
3. Add a `deploy-<trip>.yml` workflow modeled on the existing one.

## Conventions

- **Conventional Commits** with scope: `feat(seoul-app): …`, `fix(split-bill): …`, `chore(config): …`.
